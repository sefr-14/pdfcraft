PDF Overlay: third-party licence texts for the Windows build

The Windows zip made by .github/workflows/overlay-windows.yml contains a licenses folder with:

  THIRD-PARTY-CRATES.txt   every Rust crate compiled into pdfcraft.exe and pdfcraft-cli.exe for
                           x86_64-pc-windows-msvc, grouped by licence, with each crate's own licence
                           text and copyright lines (generated by cargo-about; see below)
  epaint_default_fonts/    the licences of egui's built-in fonts (Ubuntu Light: Ubuntu Font
                           Licence; Hack: MIT and Bitstream Vera; Noto Emoji: SIL OFL 1.1;
                           emoji-icon-font: MIT), copied unchanged from the fonts/ folder of the
                           epaint_default_fonts 0.36.2 crate, because the crate's metadata does not
                           carry the Hack and emoji-icon-font notices
  ATTRIBUTION.md           every bundled asset (icons, fonts, images, data) with author, source
                           and licence
  LICENSE-lucide.txt       Lucide icons (ISC)
  OFL-*.txt                Inter, JetBrains Mono and Dancing Script (SIL Open Font License 1.1)
  LICENSE_FOXIT            Foxit standard-14 substitute fonts in hayro-interpret (BSD-3-Clause)
  LICENSE-adobe-cmaps.txt  Adobe CMap resources in hayro-cmap (BSD-3-Clause)
  CGATS_LICENSE.txt        the CGATS001Compat colour profile in hayro-interpret (CC0-1.0)
  LICENSE-app-icon.txt     the app icon (MIT OR Apache-2.0)

The zip's top level also has LICENSE-MIT, LICENSE-APACHE, NOTICE and LICENSE-document.txt. Only
THIRD-PARTY-CRATES.txt and epaint_default_fonts/ are kept in this folder; the workflow copies the
other files from where they live in the repository, so each has one source.

Regenerate THIRD-PARTY-CRATES.txt whenever Cargo.lock or a crate's features change (after every
upstream synchronization), with network access so cargo-about can fetch licence files a crate
omits:

  cargo install cargo-about --version 0.9.3 --locked
  cargo about generate --locked --fail -c about.toml -m apps/pdfcraft/Cargo.toml \
      -o licenses/THIRD-PARTY-CRATES.txt licenses/about.hbs

pdfcraft-cli's crates are a subset of pdfcraft's (it adds only PdfCraft's own pdfcraft-automation),
so the pdfcraft graph covers both executables; check that again with `cargo tree` if the CLI gains
dependencies. about.toml's accepted list mirrors deny.toml plus the two font licences that
epaint_default_fonts declares. A crate under any other licence makes the command fail: review it
before accepting it.
